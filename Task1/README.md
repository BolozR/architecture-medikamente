# Данные и потоки

Медкарты, журналы и договоры лежат на общем диске, доступ ограничивается входом в домен. Нужно разделить данные по назначению, ограничить доступ и добавить аудит.

## Данные для защиты

| данные | где находятся | защита |
|---|---|---|
| ФИО, дата рождения, контакты | Patients, журналы, договоры | шифрование, роли, маскирование контактов в списках |
| адрес, место работы или учёбы | расширенная анкета | сбор только по цели, исключение из записи на приём и BI |
| факт обращения, диагноз, анализы | журналы, карты, JPG/PDF, RegistryByDate | медицинский домен, доступ по пациенту и эпизоду лечения, аудит |
| договоры, подписи, сканы | папки пациентов | закрытые объекты, короткие ссылки после проверки прав |
| платежи и возвраты | Excel, ККМ, 1С | роли кассы и бухгалтерии, шифрование; без хранения карты и CVV |
| кадры, зарплата, реквизиты | 1С:Бухгалтерия | отдельная кадровая группа и закрытые выгрузки |
| поставщики, цены, остатки | 1С:Торговля и склад | роли склада и бухгалтерии |
| пароли, ключи, токены | AD, IdP, служебные хранилища | хеши паролей, отдельное хранение и ротация секретов |
| аналитические выгрузки | Excel, в будущем озеро | псевдонимизация, агрегаты, контроль малых групп |

Имена папок на исходной схеме содержат ФИО и дату рождения — заменяем на внутренний ID. Дополнительно проверяем временные файлы Excel, загрузки на ПК, вложения Outlook, печать, резервные копии и свойства PDF/JPG. Эти копии могут остаться вне основного учёта.

Маскирование скрывает контакт в интерфейсе, HMAC заменяет patient_id в аналитике. Медицинский набор при этом остаётся конфиденциальным: человека можно узнать по сочетанию других признаков.

## Тегирование

теги, владельцев и связи между наборами храним в OpenMetadata. Для MVP достаточно таблицы PostgreSQL с категориями и правилами. Доступ ограничивают API и загрузчик.

Категории: `PUBLIC`, `INTERNAL`, `PERSONAL`, `MEDICAL`, `SECRET`, `UNKNOWN`. У поля может быть несколько тегов; неизвестная категория запрещает публикацию.

1. Владелец задаёт цель обработки, категорию и срок хранения;
2. загрузчик проверяет имена, типы и значения; новое поле или конфликт отправляет пакет в карантин;
3. сохраняются источник, версия правил и теги, без значений пациентов;
4. производные наборы наследуют теги. Снижение класса утверждает владелец после проверки;
5. lineage связывает источник → пакет → преобразование → набор → отчёт/модель для исправления и удаления копий.

Проверка пакетов перед загрузкой описана в [Task6](../Task6/classification.md).
