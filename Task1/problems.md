# Проблемы

Анализ по описанию компании. Шифрование, резервные копии и восстановление нужно проверить на месте.

| проблема | решение | приоритет |
|---|---|---|
| доменный вход без разграничения внутри процессов | группы AD, затем роли API и проверка пациента | P1 |
| медкарты доступны рядом с журналами и договорами | отдельный медицинский домен; ресепшену — запись без диагноза | P1 |
| нет аудита чтения и изменений | журнал действий и алерты массового доступа | P1 |
| внутренние потоки не контролируются | минимальные контракты, служебные роли, контроль выгрузок | P1 |
| имена папок раскрывают ФИО и дату рождения | внутренние ID и ограничения просмотра каталогов | P1 |
| расширенная анкета собирает лишние для записи сведения | определить цель каждого поля, убрать лишние | P1 |
| цели, основания и сроки обработки не описаны | реестр целей, учёт согласий и порядок прекращения обработки | P1 |
| двойной учёт оплат | 1С — источник бухучёта, сверка по ID операции | P1 |
| разные Excel могут содержать дубли пациентов | patient_id, таблица соответствий, ручной разбор спорных совпадений | P1 |
| один сервер и неизвестное состояние копий | резервирование, отдельное хранилище копий, проверка восстановления | P1 |
| будущий API может открыть чужую карту | проверка владельца в каждом запросе и скачивании, отрицательные тесты | P1 |
| возможные копии в почте, на ПК и в печати | инвентаризация, регламент выгрузок, ссылки вместо вложений | P2 |
| BI/AI создают производные медицинские наборы | карантин, restricted-слой, минимизация и lineage | P2 |
| сотрудники продолжают работать в старых файлах | пилот, обучение, read-only после переключения | P2 |

P1 — до пилота, P2 — в ходе миграции. Сначала закрываем общие папки, проверяем восстановление и ограничиваем выгрузки. Затем переносим пациентов и запись.

## Требования

| ориентир | как учитываем |
|---|---|
| 152-ФЗ, ст. 5, 6, 10 | реестр целей и оснований; сведения о здоровье выделены отдельно; лишние поля не собираем |
| 152-ФЗ, ст. 18, 19, 21 | базы, озеро и резервные копии размещаем в РФ; вводим контроль доступа, журналирование и обработку запросов субъектов |
| 323-ФЗ, ст. 13 | защищаем также сам факт обращения за медицинской помощью; диагнозы не нужны ресепшену, складу и провайдеру уведомлений |
| ПП РФ № 1119 и приказ ФСТЭК № 21 | до внедрения определяем угрозы и уровень защищённости, затем выбираем необходимые меры и средства |

Источники: [152-ФЗ](https://mintrud.gov.ru/docs/laws/130), [323-ФЗ, ст. 13](https://www.consultant.ru/document/cons_doc_LAW_121895/9f906d460f9454a8a0d290738d9fc2798c1e865a/), [ПП № 1119](https://www.consultant.ru/document/cons_doc_LAW_137356/92d969e26a4326c5d02fa79b8f9cf4994ee5633b/), [приказ № 21](https://minjust.consultant.ru/documents/6146?items=10). Соответствие системы требует отдельной проверки.

При отзыве согласия прекращается обработка, основанная на нём. Обязательные документы с другим действующим основанием сохраняются по установленному сроку с ограниченным доступом. Решение фиксирует ответственный за ПДн.

Privacy by Design: цель задаётся до сбора, доступ закрыт по умолчанию, контракт содержит только нужные поля. Новые интеграции используют общие правила и тесты, но проходят проверку назначения и состава данных.
