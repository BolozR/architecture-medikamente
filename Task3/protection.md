# Защита данных

шифруем рабочие данные, выгрузки и резервные копии. Доступ ограничиваем по ролям и пациенту: одного шифрования диска для этого недостаточно.

## Классификация

| данные / класс | состояние | зачем защищать | инструменты |
|---|---|---|---|
| контакты — PERSONAL | БД, договоры; передача через портал | раскрытие личности | шифрование диска, TLS, роли, маскирование |
| карты и анализы — PERSONAL + MEDICAL | БД, сканы; лабораторный API | утечка здоровья, подмена результата | закрытое хранилище, шифрование, mTLS, проверка пациента и заказа |
| платежи и договоры — PERSONAL + INTERNAL | 1С; платёжный обмен | раскрытие финансов, повтор оплаты | роли, TLS, сверка ID операции; без хранения карты и CVV |
| кадры и зарплата — PERSONAL | 1С, выгрузки | утечка реквизитов | кадровая группа, шифрование, контроль экспорта |
| цены и остатки — INTERNAL | склад; обмен 1С | подмена и раскрытие коммерческих данных | роли 1С, изоляция обмена, сверка |
| пароли и ключи — SECRET | система входа, хранилище секретов | захват доступа | хеши паролей, отдельное хранение ключей, ограниченные права |
| медицинские выгрузки — MEDICAL | озеро; пакетная загрузка | массовая утечка, повторная идентификация | шифрование, псевдонимизация, доступ по цели |
| агрегаты — INTERNAL | BI-витрины | определение пациента по редкому случаю | укрупнение групп, контроль фильтров и выгрузок |
| услуги и цены — PUBLIC | сайт; HTTPS | подмена информации | TLS, права на изменение |
| неизвестные поля — UNKNOWN | вход аналитики | пропуск чувствительных данных | карантин до разбора |
| аудит — PERSONAL + INTERNAL | журнал, архив | раскрытие действий, удаление следов | отдельные роли чтения и записи |

Связь оплаты с лечением также получает `MEDICAL`. Псевдонимизация не делает медицинскую выборку общедоступной.

## Хранение и передача

на Windows используем BitLocker и группы AD. Для PostgreSQL шифруем том и резервные копии, документы храним в закрытом S3 с шифрованием. Ключи держим отдельно от данных, доступ к ним ограничиваем. Восстановление проверяем вместе с доступностью ключей.

| канал | защита |
|---|---|
| портал, API, БД, хранилище | TLS с проверкой сертификата |
| лаборатория | mTLS и проверка прав на заказ |
| платёжный провайдер | HTTPS, проверка подписи ответа и суммы |
| филиал — офис | VPN и межсетевой экран |
| ККМ и файловые 1С | изолированный локальный сегмент, внешний обмен через HTTPS-адаптер |
| файловый сервер | SMB 3 с шифрованием после проверки совместимости |

## Автоматический контроль

| проверка | реакция |
|---|---|
| чужой ресурс, новые поля, ПДн в логах — тесты перед выпуском | блокировка релиза |
| неизвестная схема при загрузке | карантин пакета |
| срок сертификата, ошибки копирования | алерт администратору |
| массовое чтение, повторные отказы доступа | алерт и проверка журнала |
| срок хранения, прекращение цели обработки | ограничение доступа и удаление разрешённых копий |

## Реестр средств

| средство | тип | назначение |
|---|---|---|
| AD, ACL, роли 1С | ПО | разграничение доступа отделов |
| BitLocker, TPM при наличии | ПО и аппаратный модуль | защита диска Windows |
| шифрование томов Linux и S3 | ПО | БД, документы, выгрузки |
| Keycloak | ПО | вход, MFA, роли |
| KMS / хранилище секретов | сервис | отдельное управление ключами |
| межсетевой экран и VPN | аппаратный или виртуальный комплекс | изоляция сегментов и связь филиалов |
| TLS и сертификаты | ПО | защита каналов |
| отдельное резервное хранилище | оборудование и ПО | зашифрованные копии |
| OpenMetadata и классификатор | ПО | теги и проверка загрузок |
| аудит и VictoriaMetrics | ПО | журнал действий и алерты |

Это предлагаемые средства, настройки в действующей системе не проверялись. Требования к средствам защиты уточняются по модели угроз; основания — в [Task1](../Task1/problems.md).
